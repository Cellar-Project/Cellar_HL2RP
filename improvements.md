# Fixes and improvements for `gamemodes/ixhl2rp/plugins`
## Problem statement
A scan of `gamemodes/ixhl2rp/plugins` found a number of real bugs (infinite recursion, inverted access checks, undefined identifiers, broken predicates), security issues (a console command that any player can use to cloak), several hot-path performance smells, and a long tail of typos and dead code. These are independent from the asset-decoupling effort already described in `fix_plan.md`, which is unaffected by this plan.
The goal of this plan is to fix the bugs that actually break gameplay or expose abuse, and clean up the smaller issues that show up during the audit.
## Current state
The plugins live in three trees: `gamemodes/helix/plugins` (stock helix, mostly untouched), `addons/serverguard/lua/plugins` (admin mod, out of scope), and `gamemodes/ixhl2rp/plugins` (the schema's gameplay code, which is the focus of this plan). The schema-level tree mixes folder-style plugins (e.g. `!!core`, `!damagesystem`, `apocalypse`, `!sc_cellargui`, `!character`) with single-file plugins at the top level (e.g. `doorsaving.lua`, `holsteredswep.lua`, `wakeupmessages.lua`).
Many of these single-file plugins are imports from older Clockwork/Helix releases adapted in-place; some have shared globals (`MOOD_NONE`, `HOLSTER_DRAWINFO`, etc.) and depend on third-party addons (`prone`, `sharpeye`, `arccw`, `simfphys`, `nz_base`, ServerGuard, StormFox2). The bugs below were found by reading the code, not by running the server.
## Proposed changes
### 1. Critical correctness bugs that should be fixed first
These bugs either crash, allow abuse, or silently disable a feature. They are independent of each other and can be fixed in any order.
* `plugins/wakeupmessages.lua:20`: `if not (ply:IsValid() or ply:Alive()) then return end` is logically inverted; the `or` should be `and` (`if !IsValid(ply) or !ply:Alive() then return end`). As written it almost never aborts and the wake-up music/fade fires for invalid players.
* `plugins/dynamic_hands.lua:65-81`: `string.Explode("/", model)` returns a table, which is then passed to `player_manager.AddValidModel(shortname, model)` and `AddValidHands(shortname, ...)`. The shortname must be the last segment, e.g. `shortname = string.GetFileFromFilename(model):sub(1, -5)` or `shortname[#shortname]`. As written the registration is effectively useless.
* `plugins/!!core/libs/sh_item.lua (105, 133)`: `ix.item.Register2` references `oldBase` and `isBaseItem`, but both are local to `ix.item.New2`. `oldBase` is always `nil` here (so the rebase block is dead code) and `isBaseItem` resolves to a global that is almost certainly nil (so base items are placed into `ix.item.list` instead of `ix.item.base`). Plumb both values onto `ITEM` (e.g. `ITEM._oldBase`, use `ITEM.isBase`) or pass them as parameters.
* `plugins/!damagesystem/sv_plugin.lua:217` and `plugins/!damagesystem/sv_hooks.lua:217`: inside `PLUGIN:DoPlayerDeath`, `weapon:Transfer(nil, nil, nil, self)` passes the plugin table as the player. Use `client`.
* `plugins/!damagesystem/sv_hooks.lua (1043-1072)`: `PlayerLimbTakeDamage` references `weapon` and `targetCharacter` in its arm-damage branch, but neither is defined in scope (only `client`, `limb`, `damage`, `character`, `hitgroup` are). The whole branch is currently a no-op or errors when entered. Rewrite the branch using `character` (and re-derive whatever weapon reference is actually intended).
* `plugins/!damagesystem/sv_hooks.lua (9-20)`: the `Entity:DispatchTraceAttack` override calls `oldDispatchAttack` both inside the early-return branch and after it, so `EntityTraceAttack` returning `false` cannot actually skip the original call (and damage is processed twice on the way out). Either return after the first call, or only call `oldDispatchAttack` when the hook does not return `false`.
* `plugins/!damagesystem/sh_plugin.lua (132)` and `OnChatAdd` for `dmgAdminMsg`: the gate is `if !CAMI.PlayerHasAccess(LocalPlayer(), "Helix - Admin Chat", nil) then return end`, which silently swallows messages for the local admin instead of letting them through. Invert the check to gate non-admins instead.
* `plugins/apocalypse/sh_plugin.lua:96-100`: the timer guards on `if not character then timer.Remove(timerID) end` but `character` is a captured table reference and is always truthy. Replace with an `IsValid(character:GetPlayer())` check (or any other liveness signal) so dead characters actually clean up.
* `plugins/apocalypse/sh_plugin.lua:153`: `local ENT = scripted_ents.GetStored("nz_base").t` is evaluated at file scope. If the `nz_base` nextbot addon is not installed the file fails to load. Wrap the override in `if scripted_ents.GetStored("nz_base") then ... end` or move it into an `OnEntityCreated` / `Initialize` hook.
* `plugins/apocalypse/sh_plugin.lua (175, 197)` and `plugins/apocalypse/cl_hooks.lua:4`: `v:GetCharacter():GetData(...)` and `LocalPlayer():GetCharacter():GetData(...)` crash when no character is loaded. Add `local char = ...:GetCharacter(); if (!char) then return end`.
* `plugins/!!!anonymous/sv_plugin.lua:58-59`: `require("statusx")` and `require("query")` are raw `require` calls; if either binary module is missing the entire schema fails to start. Wrap in `pcall` and gate the dependent hooks on the result, or move them to a soft-dependency loader.
* `plugins/!!!anonymous/sv_hooks.lua (13-32, 34-48)`: `CheckPassword` issues an async SQL query, then `PlayerInitialSpawn` reads `self.stored[steamID]` immediately. There is a window where the value is missing and `client:SetNetVar("AnonID", GenerateAnonID64(steamID))` runs while a different anon ID exists in the database. Either populate `self.stored` synchronously before `PlayerInitialSpawn` (using a hook that fires after the callback) or skip caching and always read from the DB.
* `plugins/observer_enhanced.lua:288`: `ix.option.Get("observerESP", true)` references an option that is never registered (only `observerShowItemESP` and `observerShowVendor` exist), so the gate is effectively always true. Either register `observerESP` or replace the check with one of the registered options.
* `plugins/offlinebans.lua (100, 145)`: `self:OnCheckAccess(v)` is undefined for these `ix.command.Add` definitions; the broadcast loop currently reaches no one. Replace with a `CAMI.PlayerHasAccess(v, "Helix - Ban Character", nil)` check (or whatever privilege is intended).
* `plugins/zoutlands` and `plugins/!damagesystem`: confirm `Player:InOutlands` is defined somewhere before `SetCriticalState` calls it (`!damagesystem/sv_hooks.lua:39, 247, 265`); if it lives in `zoutlands` and that plugin is disabled the crit flow errors. Add a defensive `client.InOutlands and client:InOutlands()` guard.
### 2. Defensive fixes for soft-dependency plugins
Many plugins assume third-party addons or other plugins are loaded; if any are missing the file errors at load or at runtime.
* `plugins/admin_chat.lua:48`, `plugins/!!core/sh_plugin.lua:53`, `plugins/observer_enhanced.lua:226`: `serverguard.ranks:GetRank(serverguard.player:GetRank(speaker)).texture` errors when ServerGuard is absent or `GetRank` returns nil. Wrap in `serverguard and serverguard.ranks and ...` and fall back to `"icon16/user.png"`.
* `plugins/pronesupport.lua` and `plugins/!damagesystem/sv_hooks.lua (1740-1751)`: depend on a `prone` addon. Guard with `prone and prone.Exit` / `hook.Add("prone.CanExit", ...)` only registering when the addon is present.
* `plugins/legs.lua:132, 168`: `sharpeye` global is referenced. The `sharpeye and sharpeye.GetStamina` check is fine, but `sharpeye_focus:GetBiaisViewAngles()` should also be guarded the same way.
* `plugins/tempflags.lua:20`: `ix.plugin.Get("sh_playerflags")` is evaluated at file scope; if `sh_playerflags` loads after this, the cached `plyFlagsPlugin` stays nil forever and every command/hook silently no-ops. Move the lookup into the runtime functions or recheck inside an `InitializedPlugins` hook.
* `plugins/!damagesystem/sv_hooks.lua:918`: `ix.plugin.list["apocalypse"]:InfectCharacter(...)` errors if the `apocalypse` plugin is disabled. Use `ix.plugin.Get("apocalypse")` (already used elsewhere in the same file at line 1220) and nil-check the result.
### 3. Performance and resource hygiene
* `plugins/gasmask_overlay.lua:12`: `Material("gasmask/MetroMask1")` and `matOverlay:SetInt("$ignorez", 1)` run every `RenderScreenspaceEffects` tick; also `matOverlay` has no `local` and pollutes globals. Cache the material once at file scope and set its parameters once.
* `plugins/observer_enhanced.lua:228`: `Material(hook.Run("GetPlayerIcon", player) or icon)` runs every frame inside `GetPlayerESPInfo`. Cache per-player or per-icon.
* `plugins/holsteredswep.lua:188-193`: when a weapon becomes invalid, the model is `:Remove()`d but the entry is never cleared from `client.holsteredWeapons`, so the next pass tries to use the removed model. Set the entry to nil after removing.
* `plugins/holsteredswep.lua:209-212`: `client:LookupBone` plus `client:GetBonePosition` is unreliable for live players; consider `client:GetBoneMatrix(boneIndex)` and read `:GetTranslation()` / `:GetAngles()` instead, which is the pattern Helix uses elsewhere.
* `plugins/displaychat.lua:24-29`: `surface.CreateFont("awDisplayChat32", { font = genericFont, ... })` uses an undefined `genericFont` global at file scope, so the font silently falls back. Move the font creation into a `PLUGIN:LoadFonts(font, genericFont)` hook (Helix passes both fonts in).
* `plugins/displaychat.lua:91`: the comment claims `0.003 == 1/300`, but `1/300` is `0.00333...`. Either fix the constant or the comment; the distance falloff is currently slightly off.
* `plugins/nightvision.lua:48-51, 86`: `AlphaPasses` is set to `1.8` (and to `1` on low DX), but used as a loop bound `for i = 1, AlphaPasses do`. Lua iterates only once for `1.8`; clamp to an integer before the loop or design the constant as one.
* `plugins/!!!anonymous/sv_hooks.lua:67`: `cache_steamid` grows without bound for the server's uptime. Either move it to a per-call scope or expire entries.
* `plugins/thirdperson_no_abuse.lua (122-136)`: wraps `DrawWorldModel` for every weapon at file load; weapons added after load (e.g. via late workshop or runtime registration) are not patched. Move the wrap into `weapons.OnLoaded` or an equivalent hook.
* `plugins/npc_relations.lua:27`: `local relations = faction.npcRelations` is read without checking that `faction` exists; if a player has an unknown faction index this errors. Add `if (!faction) then return end`.
### 4. Smaller correctness/code-quality fixes
* `plugins/factions_use.lua:1`: `Resctiction` typo; fix to `Restriction`.
* `plugins/head_bob.lua (7-13, 23, 56)`: `headBobSacle` typo runs through the option key, the localization keys, and `ix.option.Get` calls. Rename to `headBobScale` consistently. Provide a one-time migration that copies the old option value if it exists.
* `plugins/emotemoods.lua (17-22)`: the russian language table values are still English (`Default`, `Relaxed`, ...). Replace with actual translations.
* `plugins/npc_loot.lua:56`: leftover `print(NPC:GetClass())` debug call. Remove.
* `plugins/antibunnyhop.lua:8`: `string.find(bind, "+walk")` uses Lua pattern syntax where `+` is special. Use `string.find(bind, "+walk", 1, true)` or escape to `%+walk`.
* `plugins/checkammo.lua:39-43`: the `ix.chat.Send` call is gated by `if CLIENT then` even though `ix.chat.Send` only does anything serverside. Drop the `CLIENT` gate (the file already early-returns on combine) and dispatch from server.
* `plugins/searchragdoll.lua:18-22`: `clientTarget = IsValid(target.ixPlayer) and target.ixPlayer or target` falls through to the doll itself when `ixPlayer` is unset, then immediately calls `:GetCharacter()`. Add a guard so the search just fails gracefully for ragdolls that no longer reference a player.
* `plugins/shootlock.lua:51-52`: temporarily renames the player via `client:SetName(name)` to use them as an IO target, but never restores the original name. Switch to a unique invisible target entity (or a `targetname` on the door) so player names are not mutated as a side effect.
* `plugins/propkillprotection.lua:30`: `attacker.ixHeldOwner` is read without re-checking `IsValid(attacker)`. Add the guard to avoid touching `NULL`.
* `plugins/ragdollfix.lua:30`: `hook.Run("OnCreatePlayerServerRagdoll", self)` should also pass the new ragdoll entity (`self, entity`) so consumers don't have to guess.
* `plugins/admincontextinventory.lua:34`: `entity:GetCharacter():GetName()` and `:GetInventory()` are called without checking that the target has a character (e.g. when staff right-click a player still loading). Add an early return.
* `plugins/copyanonid.lua:30`: same missing-character guard before `entity:GetCharacter():GetName()`.
* `plugins/!sc_cellargui/gui/cl_cellarinformation.lua:152` and the surrounding class button: gates UI on `FACTION_ZOMBIE`/`FACTION_SYNTH` which are not defined anywhere in the audited schema (also called out in `fix_plan.md`). Either define these constants where intended or remove the dead UI path.
* `plugins/!character/sh_plugin.lua:8`: `//ix.util.Include("sh_humannames.lua")` is commented out but the file is the largest in `!character`. Decide whether name validation is supposed to use it; if yes, re-enable; if no, delete the file.
### 5. `zfarming` plugin
The farming plugin has its own cluster of bugs that are large enough to call out separately.
* `plugins/zfarming/sh_plugin.lua:10` and `plugins/zfarming/entities/entities/ix_plant.lua:33`: the `phaseTime` config is documented as "minutes" with a default of `1800`, but `ix_plant.lua` then multiplies it by `60` again before passing to `timer.Create`. With the default, one growth tick takes `1800 * 60 = 108 000` seconds (30 hours), so plants effectively never grow on a default install. Either change the default to a reasonable value (e.g. `30`) or drop the `* 60` in the entity (and update the description to whichever unit is kept).
* `plugins/zfarming/sh_plugin.lua (70-82)` and `ix_plant.lua (97-124)`: `PLUGIN.itemReplacers` is defined but never used; `OnSelectWater` instead calls `inventory:Add(item.junk)` from the consumed water item directly. Either delete `itemReplacers` or change the watering code to read replacements from it (and remove the dependency on `item.junk`, which is undocumented).
* `plugins/zfarming/items/farming/sh_seeds_carrot.lua`, `sh_seeds_papaver.lua`, `sh_seeds_potato.lua`: none of the seed items declare `ITEM.base = "base_farming"`, so they don't inherit the `Plant` function from `items/base/sh_farming.lua`. As written they are inert items that cannot be planted at all. Add `ITEM.base = "base_farming"` to each.
* `plugins/zfarming/items/food/sh_potato.lua`: same problem on the consumable side — no `ITEM.base`, so `dHunger`/`dThirst`/`dUses` go unused (the food plugin's `base_food` is what wires those into actual consumption). Add the appropriate `ITEM.base` (likely `"base_food"`).
* `plugins/zfarming/sv_hooks.lua (20-36)`: `local data = self:GetData() or {}` followed by `if (data) then ... end` is dead-guarded (the `or {}` makes the check always true). Simplify by dropping either the `or {}` or the `if`. More importantly, the loader replays save data after `entity:Spawn()`, so `Initialize` runs first, immediately restarts the phase timer, and overwrites the random model — then the saved netvars are applied. Set the model and call `SetPlantClass` **before** `Spawn()`, and after restoring `dead`/`grown`/`phase` cancel the phase timer when the plant is already dead or already fully grown. Otherwise dead plants keep ticking and grown plants re-trigger `EndGrowth` on every tick after a server restart.
* `plugins/zfarming/sv_hooks.lua` save format: `dead`/`grown` are persisted but the loader never calls `Die()` or `EndGrowth()` to re-establish their side effects (timer removal, `grown` netvar). Add explicit handling in `LoadData` so the entity's lifecycle matches the saved state.
* `plugins/zfarming/entities/entities/ix_plant.lua:19`: `self:SetCollisionBounds(pos - Vector(3, 3, 3), pos + Vector(3, 3, 3))` passes world-space coordinates as the bounds. `SetCollisionBounds` expects mins/maxs **relative to the entity** — use `Vector(-3, -3, -3)`, `Vector(3, 3, 3)`. As written the bbox lives somewhere on the map far away from the plant.
* `plugins/zfarming/entities/entities/ix_plant.lua:32`: timer name `"phasetimer" .. self:EntIndex()` collides with the timer of any future entity that gets the same EntIndex after this one is removed. Use `tostring(self)` or a UUID instead so timers can never alias.
* `plugins/zfarming/entities/entities/ix_plant.lua (39-49)`: each phase tick also subtracts `0.5` from `health`. With default config `phaseRate=10`, `phaseMaxPoints=50`, `phases=4`, plants take `5 * 4 = 20` ticks to grow, which removes exactly `10` health — i.e. unwatered plants die at the same moment they would have ripened. Either decouple the health drain from the growth tick rate (e.g. tie it to `phaseRate / phaseMaxPoints` so total drain is consistent regardless of config) or make it configurable.
* `plugins/zfarming/entities/entities/ix_plant.lua:79, 84`: harvest loops are `for k = 0, productAmount do` and `for k = 0, seedsAmount do`, both off-by-one — they spawn `productAmount + 1` items / `seedsAmount + 1` seeds. Use `for k = 1, productAmount do`. Also `math.random(0, skill)` on line 82 will error when `skill < 0`; clamp it to `>= 0` first.
* `plugins/zfarming/entities/entities/ix_plant.lua:69, 73`: `self.item` may be nil if `SetPlantClass` was passed a class that doesn't resolve (e.g. a class that was renamed/removed since the plant was saved). Bail out gracefully in `OnSelectHarvest` / `GetPlantClass` when `self.item` is missing.
* `plugins/zfarming/entities/entities/ix_plant.lua (90-95)`: `OnSelectDestroy` only checks distance — anyone in range can destroy any plant. If destruction is meant to be owner-only, track the planter (set on plant creation in `sh_farming.lua`) and gate the menu / handler.
* `plugins/zfarming/entities/entities/ix_plant.lua (108-122)`: the watering loop iterates `pairs(inventory:GetItems())` and stops at the first matching drink, but `pairs` order is undefined, so the player may consume their best water item while a worse one was available (or vice versa). Pick the lowest-tier valid water item explicitly. Also guard `local junk = item.junk; ... inventory:Add(junk)` against `junk == nil`, otherwise `inventory:Add(nil)` errors.
* `plugins/zfarming/items/base/sh_farming.lua (26-30)`: `Plant` checks `tr.Hit and surfaces[tr.MatType]` and rejects players, but does not reject other movable entities. Currently a seed can be planted on top of a prop or vehicle and the plant will float once that entity moves. Add `tr.HitWorld` (or a `tr.Entity:GetMoveType() == MOVETYPE_NONE` check) to the surface guard.
* `plugins/zfarming/items/base/sh_farming.lua` and `ix_plant.lua`: the planter's character is never recorded on the plant, which is also why ownership-aware destruction in the bullet above isn't possible today. Capture `client:SteamID64()` (or character ID) on the plant in `Plant`'s `OnRun` and persist it in `SaveData`/`LoadData`.
* `plugins/zfarming/entities/entities/ix_plant.lua (175-203)`: `OnPopulateEntityInfo` calls `title:SetText(self:GetPlantName())`, but the `name` netvar isn't initialized until the planter calls `SetPlantName`. New plants briefly have a `nil` name and `SetText(nil)` errors on some derma versions; default to an empty string in `GetPlantName` (or in `SetPlantName` at spawn).
* `plugins/zfarming/items/sh_papaver.lua:3`: `models/crunchy/props/re4_props/herb_green_mix.mdl` is third-party content. Route the model through whatever fallback layer the asset-decoupling work in `fix_plan.md` lands.
## Review-only items
These behaviors look intentional but are worth confirming with the project owner before changes are made.
* `plugins/familyrestrict.lua` hard-kicks every family-shared account except for two hard-coded SteamID64s. If that allowlist is meant to be data-driven, move it to `Schema.config` or a separate file.
* `plugins/!!!anonymous/sv_plugin.lua (4-5)`: `COMMUNITY_ID` and `SECRET` are encoded in source. Confirm they are not meant to be configurable per server.
* `plugins/edictlimit.lua:9`: hard-coded `7900` threshold. Confirm whether this should be a config value.
* `plugins/wakeupmessages.lua:23`: plays a music file via `ConCommand("play music/...")` on every spawn. Decide if this should fire only on first spawn per session or be removed entirely.
## Validation
* Static check by grepping for the bug patterns this plan removes (e.g. `self:DoorSetAccess(client, door,`, `"freshdead_01.mdll"`, `headBobSacle`, `Resctiction`, `print(NPC:GetClass())`).
* In a local server, exercise: door admin commands on a parented door pair; `/cmb_cloak` denial for non-assassin players; admin chat for both an admin and a non-admin account; offline character ban with at least two admins online to confirm broadcast; first wake-up after a fresh spawn; gasmask overlay performance; observer ESP visibility; apocalypse infection through a fists hit (uses `ix.plugin.Get("apocalypse")`).
* Plugin-load smoke: start the schema with `nz_base`, ServerGuard, `prone`, `sharpeye`, `sh_playerflags`, and `apocalypse` each disabled in turn and confirm no plugin errors at boot.
## Migration strategy
Land the changes in this order to minimize risk of regressions:
1. Critical correctness bugs in section 1 (each is local; no cross-plugin coordination needed).
2. Defensive guards in section 2 (purely additive; safe to merge any time).
3. Performance/resource fixes in section 3.
4. Cleanups in section 4 plus any review-only items the owner approves.
This is independent of the asset-decoupling work in `fix_plan.md`; the two plans can run in parallel.
## Expected result
After this plan is implemented, the schema should boot cleanly when optional addons are missing, the door, admin-chat, assassin-cloak, wake-up, dynamic-hands, item-base, damage-system death-drop, and apocalypse infection paths all do what their code says they do, and the long tail of typos, dead code, and per-frame allocations in the UI plugins is removed. The server still depends on the same content packs as before, but the schema's own logic stops actively working against itself.
